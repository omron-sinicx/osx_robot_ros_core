# 2026-08-10 D455 RGB 色調チューニング

## Topic

d455_1/2/3 の RGB 露出・ホワイトバランス・彩度を白い紙を基準に実測で決定し、
launch ファイルへ反映した。あわせて depth 側の露出も掃引し、オートのままとする判断をした。
用途は NeRF による三次元再構築。

## Summary

- RGB を `exposure 31 / white_balance 4300 K / saturation 60` に変更 (旧: 60 / 3700 / 70)。
  旧値は d455_0 からの未検証の流用で、白飛びとホワイトバランスのずれが同時に起きていた
- 露出とホワイトバランスは飽和しない範囲でほぼ独立。5x5 格子で確認したので、
  今後は 1 次元ずつ順に詰めれば足りる
- depth はオート露出が最適。手動の最良値と同等 (有効画素 83.4%) で、手動化の利点がない
- ブランチを `dev-ak` に統合。3 本の dev ブランチは完全に直列だったため、改名だけで済んだ

## History

### 発端

接続中の RealSense を確認したところ D455 が 3 台 (`142422250629`, `146222253334`,
`138322252534`)。設定値を読むと、depth はオート露出だが **RGB は 3 台とも手動固定**で、
`exposure 60 / WB 3700 K / saturation 70` が入っていた。リポジトリの launch には
露出系の指定がないと最初に判断したが、これは誤りで、起動元は
`osx_bringup_d455s.launch` → シリアル別の個別 launch という構成だった。
個別 launch に `rgb_lock_settings=true` と各値が書かれており、
コメントには「141322250927 と同じチューニング値を初期値として継承」とあった。
つまり実測ではなく他機からの流用だった。

### 最初の観測と誤診

1 フレーム取得して見たところ、チェッカーボードの白マスが明確にピンクに転んでいた。
チャンネル平均は B 136 / G 139 / R 118 で赤が低く、全体としてはシアン寄り。
局所ではマゼンタ、全体ではシアンという食い違いを、当初は WB 3700 K のずれと
saturation 70 の組み合わせと見立てた。

白マスを測ると R 251.9 / G 212.0 / B 254.8 で、**R と B がクリップしていた**。
ここで白基準として使えないことが判明。露出を下げて飽和を解消する必要があった。

この誤診は後に完全に解けた。露出掃引で R/G・B/G を追うと、露出 33 までは 1.0 付近で
安定し、40 以降で 1.16〜1.19 に跳ね上がる。G が先に 255 で頭打ちになる一方
R と B がまだ伸びるため、比が見かけ上ふくらんでいただけだった。
**最初に見たマゼンタかぶりの正体は色の問題ではなく露出過多**。
WB のずれも実在したが、二つが重なって観測を混乱させていた。

### 白基準の確保

ユーザーが画角中央に白い紙を設置。このとき WB が 3700 K から 5500 K へ
変わっていることに気付いた (こちらの変更ではない)。前後の測定で
3700 K は B/G 1.10 で青すぎ、5500 K は B/G 0.70 で黄色すぎ。
線形外挿で 4100〜4200 K あたりが適正と当たりを付けた。

### 掃引

紙を基準に、露出 20 固定で WB を 3700〜5500 K の 200 K 刻みで掃引。
誤差 `|R/G - 1| + |B/G - 1|` が最小の **4300 K** を採用 (R/G 0.992, B/G 0.969)。
外挿予測とほぼ一致した。

次に WB 4300 K で露出を掃引。露出 34 で紙の飽和が 1.5% から 21% へ跳ね上がる崖を確認し、
崖の手前の 28 を選択。

その後 5x5 の格子 (WB 4100〜4500 × 露出 22〜34) で確認したところ、
**4300 K の行が全列で最小**だった。飽和しない範囲では R/G・B/G が露出でほとんど動かず
(露出 22→31 で 0.5% の変化)、両者が独立であることが確認できた。
格子の最小は WB 4300 / 露出 31。

格子の 2 点 (`4400/22`, `4300/34`) が傾向から外れたが、設定反映の待ち時間 1.1 秒が
不足して前条件のフレームを掴んだ可能性が高い。最適解の周辺ではないため結論に影響なし。

### gain / gamma / saturation

未検証のまま残っていた 3 つも掃引した。

- **gain 64**: 上げる余地なし。96 以上で紙が飽和し R/G が 1.21 に壊れる
- **gamma 450**: 暗部の持ち上げ量を決める (300 で暗部 14.1、600 で 33.5)。
  ノイズには無関係で、450 と 550 で色ノイズが完全に同一だった。変更せず
- **saturation 70**: 明るさを変えず色差だけ増幅する。色ノイズも一緒に増える

NeRF のフローター懸念から saturation を検討。輝度帯別に時間ノイズを測ると、
暗部の色ノイズが 40 で 1.69、55 で 2.05、64 で 2.29、70 で 3.16、85 で 5.58。
暗部が画像の 25% を占め、そこのノイズは明部の 2 倍以上あった。

55 を試したところ「色あせすぎ」との判断で 60 へ。65 も試したが、
55→60 の色ノイズ増が 3% なのに対し 60→65 は 29% と急増する。
**60 と 65 の間に折れ点**があり、60 で止めるのが合理的と判断。
一度 65 を選ぶ流れになったが、最終的に「素直だから」という理由で 60 に確定した。

### 平均化との関係

フレーム平均後の残留ノイズも測定した。8 枚平均で輝度ノイズは 60/65 とも 1.13 で
**差がない** (saturation は色差のみを扱うため)。色ノイズは比としては +24% を保つが、
絶対差は 8 枚平均で 0.16 階調と、8 bit の量子化幅を下回る。

撮影方式は「三脚固定 + アームで物体を回して視点多様性を確保」。
カメラが動かないので、静止させて複数フレーム撮り平均する方式に視点の損失がない。
この場合 60 と 65 の差は実質消えるが、最終的に 60 を採用した。

なお、この構成では物体から見た照明方向が姿勢ごとに変わる。この輝度差は数十階調に達し、
センサノイズ (0.2 階調程度) より桁違いに大きい。appearance embedding は導入済みとのこと。

### depth

露出を 1000〜120000 µs で掃引し、有効画素率で評価。オートが 83.35% (作業台領域 98.03%)、
手動の最良は 6000 µs 付近で 83.37% と**同等**。作業台領域ではオートが全条件中最高だった。

12000 µs を超えると急激に悪化し、33000 µs では作業台の有効画素が 30.7% まで低下。
環境光が積算されて IR ドットパターンが背景光に埋もれ、視差が取れなくなるため。
RGB の「明るくすれば見える」とは逆の挙動。

掃引前に読めた `exposure 33000` はオート有効時の表示で、実際に使われている値ではなかった。

### ブランチ整理

`osx_core` に dev ブランチが 3 本あり分かりにくいとのことで統合を検討。
調べると 3 本は完全に直列 (`dev-another_ur5e` ⊂ `dev-d455_multicam_bringup` ⊂
`dev-handeye_calibration_refactor`) で、古い 2 本に固有のコミットは 1 つもなかった。
最新の 1 本を `dev-ak` に改名し、他 2 本をローカルで削除するだけで統合が完了。
履歴は一切変わっていない。リモートは他者への影響を避けるため触っていない。

## Decisions

- RGB を exposure 31 / WB 4300 K / saturation 60 に確定 — 白紙基準の実測 + 5x5 格子掃引
- gain 64 / gamma 450 は変更せず — 掃引で動かす根拠が出なかったため
- depth はオート露出のまま — 手動の最良値と同等で、手動化の利点がない
- 3 台とも同じ値を使用 — 個体差が R/G・B/G で 5% 以内に収まったため
- ブランチを `dev-ak` に統合 (ローカルのみ) — リモートは他者影響を避け現状維持
- 手順書を `notes/debug/d455_rgb_color_calibration.md` に作成 — 再現可能性の確保
